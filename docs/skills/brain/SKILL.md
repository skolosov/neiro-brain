# /brain

Личная база знаний пользователя живёт на MCP-сервере `neiro-brain`. Список команд:

| Команда | Что делает |
|---|---|
| `/brain` | Собирает знания из текущей сессии и сохраняет их в базу |
| `/brain show` | Показывает, что было бы сохранено, но не пишет |
| `/brain help` | Показывает эту справку, в базу не ходит |
| `/brain --help` | То же самое, что `/brain help` |
| `/brain init` | Подключает MCP-сервер: спрашивает адрес и токен, правит конфиг харнесса |
| `/brain doctor` | Проверяет, что скилл, конфиг, токен и ресурс на месте |
| `/brain compact --project=<имя>` | Сливает дубли в карточках одного проекта |
| `/brain compact --theme=<тема>` | Сливает дубли в карточках одной темы |
| `/brain compact` | Сливает дубли по всей базе |

## `/brain help`

`help` и `--help` — одно и то же: оба пишут справку. Ничего не вызывай, в MCP не ходи,
просто напечатай таблицу команд из этого файла и две строки под ней:

- для работы нужен MCP-сервер `neiro-brain` и личный токен из админки, раздел «Токены»;
- если MCP отвечает ошибкой авторизации, дело в токене, а не в базе.

Если пользователь спросил справку посреди другой команды — сначала коротко ответь
справкой, потом спроси, продолжать ли прерванное.

## `/brain init`

Подключение MCP-сервера. **Токен через агента не проходит:** не спрашивай его, не проси вставить
в чат, не читай из конфига и не печатай. Токен — это ключ к личной базе; всё, что попало в
переписку, попадает и в провайдера модели. Человек вставляет его сам, в файл.

1. **Спроси адрес сервера** (например `https://brain.example.ru`), если он не дан аргументом.
2. **Определи харнесс** по признакам, а не по догадке:
   - есть каталог `~/.dsh` (Windows `%USERPROFILE%\.dsh`, macOS/Linux `$HOME/.dsh`) —
     это DeepSeek Harness, конфиг `~/.dsh/profiles/<профиль>/cordis.patch.yml`;
   - команда `claude` отвечает в PATH — это Claude Code, там родная команда;
   - macOS и Claude Desktop (`~/Library/Application Support/Claude/claude_desktop_config.json`) —
     HTTP напрямую не умеет, нужен мост `npx -y mcp-remote <адрес>/mcp/knowledge --header "…"`,
     объясни, что нужен Node;
   - ничего не подошло — напечатай фрагмент конфига и спроси, куда его положить.
3. **Дай человеку готовый текст с заглушкой** и точный путь к файлу. Пусть он откроет раздел
   «Токены» в админке, нажмёт там «Скопировать конфиг» и вставит полученный JSON (или YAML для DSH)
   сам. Если правку файла делает агент — он делает её с заглушкой `Bearer ВСТАВЬТЕ_ТОКЕН_САМИ`,
   а токен подставляет человек в редакторе.
4. **Проверь связь без токена в руках.** Если MCP уже подключён и доступен — вызови
   `list_projects` или `search_knowledge`: это и есть проверка. Если ещё нет — попроси человека
   перезапустить харнесс и набрать `/brain doctor`; curl с токеном в аргументах не запускай.
5. **Скажи про перезапуск**: харнесс читает список MCP-серверов при старте, поэтому до
   перезапуска `/brain` в этой сессии работать не будет.

Если человек сам вставил токен в чат — не повторяй его, предупреди, что токен надо отозвать
в разделе «Токены» и выпустить новый.

## `/brain doctor`

Проверка без починки. Собери таблицу и одну рекомендацию на каждую поломку:

| Что проверяем | Как |
|---|---|
| Скилл на месте | файл `~/.agents/skills/brain/SKILL.md` существует |
| MCP прописан | в конфиге харнесса есть `neiro-brain` (факт наличия, без чтения значения токена) |
| Токен живой | вызов `list_projects` проходит; 401 — токен отозван или не вписан |
| Протокол читается | ресурс `knowledge://skill/brain` отдаёт markdown |

Ничего не исправляй без явной просьбы: `doctor` — это диагноз, `init` — лечение.
Токен не показывай и не пересказывай, даже если он есть в конфиге.

## `/brain`

Сохранить знания текущей сессии. Это не «прочитать протокол», а именно разобрать разговор
и записать то, что понадобится в будущих чатах.

1. **Протокол.** Если ресурс `knowledge://skill/brain` доступен — прочитай его. Если харнесс
   не даёт инструмента чтения ресурсов, работай по `Instructions` сервера: правила там те же.
2. **Что считать знанием.** Долговременные факты: принятые решения и их причины,
   архитектура и устройство, ограничения и цифры, договорённости, стек и версии,
   пути и команды, найденные грабли, предпочтения пользователя.
3. **Что не сохранять.** Пересказ хода задачи («сначала сделали, потом откатили»),
   временные состояния, содержимое кода, которое и так лежит в репозитории, секреты
   и токены, догадки без опоры на сказанное.
4. **Дубли.** Перед записью по каждой теме — `search_knowledge`. Если факт уже есть,
   не пиши второй: замени старый через `supersedes` в `remember_many`. Если новая карточка
   не противоречит старой, а дополняет — пиши отдельную.
5. **Запись.** `remember_many`, одна карточка = один факт, до 20 за вызов.
   `scope=project` требует `project`; если обсуждался один проект — пиши про него,
   общие вещи про человека — `profile`.
6. **Отчёт.** Сколько создано, сколько заменило старые, что осталось спорным.
   Не пересказывай содержимое карточек — за него отвечает база.

`/brain show` (он же `--dry-run`) делает шаги 1–4 и печатает список карточек
с заголовками и темами, но ничего не записывает.

## `/brain compact`

С охватом: проект (`--project=<имя>`), тема (`--theme=<тема>`) или вся база.
Прочитай `knowledge://skill/brain`, раздел «Команда `/brain compact`», и выполни его:
найди дубли, покажи план слияния, дождись подтверждения, запиши объединённое
через `remember_many`, а старые карточки перечисли в поле `supersedes`.
